# Postgres adapter

The Postgres adapter exposes rows and LISTEN channels with file-native writeback discovery.

Read-only mounts:
- `/postgres/<db>/<schema>/<table>/<pk>.json` - Postgres row records.

Resources:

Schema and create example files are served under the `/discovery` mount root (`/discovery/postgres/...`), not beside the live resource directory.

| Resource | Schema | Create example | ID pattern | What it does |
|---|---|---|---|---|
| `/postgres/rows/<id>.json` | `/discovery/postgres/rows/.schema.json` | `/discovery/postgres/rows/.create.example.json` | `^[A-Za-z0-9_.:-]+$` | Creates a row. |
| `/postgres/listeners/<id>.json` | `/discovery/postgres/listeners/.schema.json` | `/discovery/postgres/listeners/.create.example.json` | `^[A-Za-z0-9_.:-]+$` | Registers a LISTEN channel. |

## Operations

| To... | Do... |
|---|---|
| Read | `cat <canonical-resource-path>` after listing the resource directory or following an alias when one is available. Use the resource table and ID patterns below to determine whether a resource uses a bare id, an adapter-specific slug/id filename, or an exact sidecar path such as `content.md`. |
| Edit | Write the resource update payload to the canonical resource path. For JSON resources, included mutable fields PATCH; fields marked `readOnly` in `.schema.json` are rejected. |
| Create | Write JSON to any non-canonical filename such as `create request.json`. The adapter creates the record at its canonical resource path and rewrites the draft as `{ "created": "<real-id>", "path": "<canonical-resource-path>", "url": "<provider-url>" }`. |
| Ignore | Editor scratch files named `partial.json`, `.tmp.json`, `.partial.json`, `*.tmp.json`, or `*.partial.json` are ignored and never treated as create drafts. |
| Delete | `rm <canonical-resource-path>` for canonical records. |

## ID Patterns
- `/postgres/rows/<id>.json`: `^[A-Za-z0-9_.:-]+$`. Filenames that do not match this pattern are treated as create drafts.
- `/postgres/listeners/<id>.json`: `^[A-Za-z0-9_.:-]+$`. Filenames that do not match this pattern are treated as create drafts.

## Write field contracts

### Create Postgres row

Resource: `/postgres/rows/<id>.json`
Schema: `/discovery/postgres/rows/.schema.json`
Create example: `/discovery/postgres/rows/.create.example.json`
Required fields: `_op`, `primaryKey`, `row`.
Optional fields: none.

Fields:

- `_op` (required, string) - Operation.
- `primaryKey` (required, string) - Primary key column.
- `row` (required, object) - Row values.

### Create Postgres listener

Resource: `/postgres/listeners/<id>.json`
Schema: `/discovery/postgres/listeners/.schema.json`
Create example: `/discovery/postgres/listeners/.create.example.json`
Required fields: `channel`.
Optional fields: `table`.

Fields:

- `channel` (required, string) - LISTEN channel.
- `table` (optional, string) - Table.

## Create Examples
Read the resource `.schema.json` under `/discovery` first, then use the sibling `.create.example.json` as a minimal create document. The example intentionally omits read-only fields.
