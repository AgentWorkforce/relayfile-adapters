# GitLab adapter

The GitLab adapter exposes projects, merge requests, discussions, issues, commits, pipelines, jobs, deployments, and tags under `/gitlab`. Relayfile writeback can create and update issues and merge requests, create branches, accept or close/reopen merge requests, and add merge request discussions and issue notes.

Read-only mounts:
- `/gitlab/projects/<namespace>/<project>/merge_requests/<iid>__<slug>/meta.json` - Merge request metadata.
- `/gitlab/projects/<namespace>/<project>/merge_requests/<iid>__<slug>/discussions/<discussionId>.json` - Merge request discussions.
- `/gitlab/projects/<namespace>/<project>/issues/<iid>__<slug>/meta.json` - Issue metadata.
- `/gitlab/projects/<namespace>/<project>/pipelines/<pipelineId>__<ref>/jobs/<jobId>.json` - Pipeline job records.
- `/gitlab/projects/<namespace>/<project>/deployments/<deploymentId>/meta.json` - Deployment records.
- `/gitlab/projects/<namespace>/<project>/tags/<tagRef>/meta.json` - Tag records.

Resources:

Schema and create example files are served under the `/discovery` mount root (`/discovery/gitlab/...`), not beside the live resource directory.

## Operations

| To... | Do... |
|---|---|
| Read | `cat <canonical-resource-path>` after listing the resource directory or following an alias when one is available. Use the resource table and ID patterns below to determine whether a resource uses a bare id, an adapter-specific slug/id filename, or an exact sidecar path such as `content.md`. |
| Edit | Write the resource update payload to the canonical resource path. For JSON resources, included mutable fields PATCH; fields marked `readOnly` in `.schema.json` are rejected. Resources that list an `Operations:` line without `update` reject this; it does not apply to resources without an `Operations:` line. |
| Create | For resources with a create example, write JSON to any non-canonical filename such as `create request.json`. The adapter creates the record at its canonical resource path and rewrites the draft as `{ "created": "<real-id>", "path": "<canonical-resource-path>", "url": "<provider-url>" }`. Resources whose ID pattern is `exact file path` are written in place and never created from drafts. Resources that list an `Operations:` line without `create` reject this; it does not apply to resources without an `Operations:` line. |
| Ignore | Editor scratch files named `partial.json`, `.tmp.json`, `.partial.json`, `*.tmp.json`, or `*.partial.json` are ignored and never treated as create drafts. |
| Delete | `rm <canonical-resource-path>` for canonical records. Resources that list an `Operations:` line without `delete` reject this; it does not apply to resources without an `Operations:` line. |

## ID Patterns
- `/gitlab/projects/{projectPath}/issues/<id>.json`: `^[1-9]\d*$`. Filenames that do not match this pattern are treated as create drafts.
- `/gitlab/projects/{projectPath}/issues/{issueIid}__{slug}/meta.json`: exact file path.
- `/gitlab/projects/{projectPath}/merge-requests/<id>.json`: `^[1-9]\d*$`. Filenames that do not match this pattern are treated as create drafts.
- `/gitlab/projects/{projectPath}/merge_requests/{mergeRequestIid}__{slug}/meta.json`: exact file path.
- `/gitlab/projects/{projectPath}/merge_requests/{mergeRequestIid}__{slug}/merge.json`: exact file path.
- `/gitlab/projects/{projectPath}/merge_requests/{mergeRequestIid}__{slug}/close.json`: exact file path.
- `/gitlab/projects/{projectPath}/refs/<id>.json`: `^$`. Filenames that do not match this pattern are treated as create drafts.
- `/gitlab/projects/{projectPath}/merge_requests/{mergeRequestIid}__{slug}/discussions/<id>.json`: `^[A-Za-z0-9_.:-]+$`. Filenames that do not match this pattern are treated as create drafts.
- `/gitlab/projects/{projectPath}/issues/{issueIid}__{slug}/comments/<id>.json`: `^[A-Za-z0-9_.:-]+$`. Filenames that do not match this pattern are treated as create drafts.

## Write field contracts

### Create GitLab issue

Resource: `/gitlab/projects/{projectPath}/issues/<id>.json`
Schema: `/discovery/gitlab/projects/{projectPath}/issues/.schema.json`
Operations: `create`.
Create example: `/discovery/gitlab/projects/{projectPath}/issues/.create.example.json`
Required fields: `title`.
Optional fields: `description`, `labels`, `assignee_ids`, `milestone_id`, `confidential`.

Fields:

- `title` (required, string) - Issue title.
- `description` (optional, string) - Markdown issue description.
- `labels` (optional, array) - Label names. The adapter sends them to GitLab as a comma-separated labels value.
- `assignee_ids` (optional, array) - GitLab user IDs to assign.
- `milestone_id` (optional, integer) - GitLab milestone ID.
- `confidential` (optional, boolean) - Whether the issue is confidential.

### Update GitLab issue

Resource: `/gitlab/projects/{projectPath}/issues/{issueIid}__{slug}/meta.json`
Schema: `/discovery/gitlab/projects/{projectPath}/issues/{issueIid}__{slug}/meta.json/.schema.json`
Operations: `update`.
Payload example: `/discovery/gitlab/projects/{projectPath}/issues/{issueIid}__{slug}/meta.json/.create.example.json`
Required fields: none at the top level.
Optional fields: `title`, `description`, `labels`, `assignee_ids`, `milestone_id`, `confidential`, `state_event`.

Fields:

- `title` (optional, string) - Issue title.
- `description` (optional, string) - Markdown issue description.
- `labels` (optional, array) - Label names. The adapter sends them to GitLab as a comma-separated labels value.
- `assignee_ids` (optional, array) - GitLab user IDs to assign.
- `milestone_id` (optional, integer) - GitLab milestone ID.
- `confidential` (optional, boolean) - Whether the issue is confidential.
- `state_event` (optional, enum) - Lifecycle event for the issue. Allowed values: `close`, `reopen`.

### Create GitLab merge request

Resource: `/gitlab/projects/{projectPath}/merge-requests/<id>.json`
Schema: `/discovery/gitlab/projects/{projectPath}/merge-requests/.schema.json`
Operations: `create`.
Create example: `/discovery/gitlab/projects/{projectPath}/merge-requests/.create.example.json`
Required fields: `source_branch`, `target_branch`, `title`.
Optional fields: `description`, `labels`, `remove_source_branch`, `draft`.

Fields:

- `source_branch` (required, string) - Existing source branch name.
- `target_branch` (required, string) - Target branch name.
- `title` (required, string) - Merge request title.
- `description` (optional, string) - Markdown merge request description.
- `labels` (optional, array) - Label names. The adapter sends them to GitLab as a comma-separated labels value.
- `remove_source_branch` (optional, boolean) - Whether GitLab should remove the source branch after merge.
- `draft` (optional, boolean) - Whether to create the merge request as a draft.

Operations: `update`.
Payload example: `/discovery/gitlab/projects/{projectPath}/merge_requests/{mergeRequestIid}__{slug}/meta.json/.create.example.json`
Required fields: none at the top level.
Optional fields: `source_branch`, `target_branch`, `title`, `description`, `labels`, `remove_source_branch`, `draft`, `state_event`.

Fields:

- `source_branch` (optional, string) - Existing source branch name.
- `target_branch` (optional, string) - Target branch name.
- `title` (optional, string) - Merge request title.
- `description` (optional, string) - Markdown merge request description.
- `labels` (optional, array) - Label names. The adapter sends them to GitLab as a comma-separated labels value.
- `remove_source_branch` (optional, boolean) - Whether GitLab should remove the source branch after merge.
- `draft` (optional, boolean) - Whether to create the merge request as a draft.
- `state_event` (optional, enum) - Lifecycle event for the merge request. Allowed values: `close`, `reopen`.

### Merge GitLab merge request

Resource: `/gitlab/projects/{projectPath}/merge_requests/{mergeRequestIid}__{slug}/merge.json`
Schema: `/discovery/gitlab/projects/{projectPath}/merge_requests/{mergeRequestIid}__{slug}/merge.json/.schema.json`
Operations: `update`.
Payload example: `/discovery/gitlab/projects/{projectPath}/merge_requests/{mergeRequestIid}__{slug}/merge.json/.create.example.json`
Required fields: none at the top level.
Optional fields: `merge_commit_message`, `squash`, `should_remove_source_branch`.

Fields:

- `merge_commit_message` (optional, string) - Custom commit message for the merge commit.
- `squash` (optional, boolean) - Whether GitLab should squash commits before merge.
- `should_remove_source_branch` (optional, boolean) - Whether GitLab should remove the source branch after merge.

### Close or reopen GitLab merge request

Resource: `/gitlab/projects/{projectPath}/merge_requests/{mergeRequestIid}__{slug}/close.json`
Schema: `/discovery/gitlab/projects/{projectPath}/merge_requests/{mergeRequestIid}__{slug}/close.json/.schema.json`
Operations: `update`.
Payload example: `/discovery/gitlab/projects/{projectPath}/merge_requests/{mergeRequestIid}__{slug}/close.json/.create.example.json`
Required fields: `state_event`.
Optional fields: none.

Fields:

- `state_event` (required, enum) - Set `close` to close the merge request or `reopen` to reopen it. Allowed values: `close`, `reopen`.

### Create GitLab branch

Resource: `/gitlab/projects/{projectPath}/refs/<id>.json`
Schema: `/discovery/gitlab/projects/{projectPath}/refs/.schema.json`
Operations: `create`.
Create example: `/discovery/gitlab/projects/{projectPath}/refs/.create.example.json`
Required fields: `branch`, `ref`.
Optional fields: none.

Fields:

- `branch` (required, string) - New branch name.
- `ref` (required, string) - Existing branch, tag, or commit SHA to branch from.

### Create GitLab merge request discussion

Resource: `/gitlab/projects/{projectPath}/merge_requests/{mergeRequestIid}__{slug}/discussions/<id>.json`
Schema: `/discovery/gitlab/projects/{projectPath}/merge_requests/{mergeRequestIid}__{slug}/discussions/.schema.json`
Create example: `/discovery/gitlab/projects/{projectPath}/merge_requests/{mergeRequestIid}__{slug}/discussions/.create.example.json`
Required fields: `body`.
Optional fields: `position`, `created_at`.

Fields:

- `body` (required, string) - Markdown note body.
- `position` (optional, object) - Optional GitLab position object for diff discussions.
- `created_at` (optional, string, date-time) - Optional timestamp for imports when supported by GitLab.

## Create Examples
Read the resource `.schema.json` under `/discovery` first, then use the sibling `.create.example.json` as a minimal create document when the resource advertises one. The example intentionally omits read-only fields.
Examples labelled `Payload example` belong to update-only resources: write them to the canonical resource path as an update payload, never as a create draft.
