# Ramp Adapter

`@relayfile/adapter-ramp` exposes one Ramp business under `/ramp` as finance-readable JSON,
stable `_index.json` lists, and webhook-safe `by-*` alias pointers. This phase is read-only:
Cloud uses the adapter's mount catalog, layout prompt, auxiliary emitters, digest handler, and
Hookdeck-aware webhook normalization, while contract-backed writeback remains deferred.

## Read Mount Summary

- `/ramp/business.json` holds the current business metadata.
- `/ramp/bills`, `/ramp/purchase-orders`, `/ramp/item-receipts`, and
  `/ramp/vendor-agreements` use directory records ending in `meta.json`.
- `/ramp/transactions`, `/ramp/reimbursements`, `/ramp/receipts`, `/ramp/vendors`,
  `/ramp/transfers`, `/ramp/repayments`, `/ramp/dimensions/**`, and
  `/ramp/accounting/**` use flat `<slug>__<id>.json` records.
- Every mounted resource publishes `_index.json` rows containing `id`, `title`, `updated`,
  and `canonicalPath`.
- Stable `by-id` pointers exist for every resource. Human-facing aliases such as
  `by-vendor`, `by-status`, `by-number`, `by-merchant`, `by-transaction`, and `by-email`
  sit on top of the canonical record paths.

## Operation Table

| Surface | Operation |
|---|---|
| Sync materialization | Canonical records are written by Cloud; the adapter emits `_index.json`, `LAYOUT.md`, `by-id`, and human-readable alias pointers. |
| Webhook routing | Hookdeck-forwarded Ramp events are normalized by `x-ramp-signature`, `x-hookdeck-eventid`, event family, and object id. |
| Digest visibility | Finance mutations are classified into digest verbs such as created, approved, paid, reimbursed, archived, closed, and canceled. |
| Writeback | Not implemented in this phase. No file-native mutation contract ships yet. |

## ID Pattern Notes

- Canonical flat records use `<slug>__<id>.json`.
- Canonical directory records use `<id>__<slug>/meta.json`.
- Alias folders use provider semantics directly, for example vendor names, invoice numbers,
  statuses, emails, purchase-order ids, transaction ids, and reimbursement ids.
- Provider ids remain Ramp ids; path helpers percent-encode path-unsafe characters before
  composing paths.

## Event And Inbound Notes

- Trigger names come from Ramp webhook semantics and intentionally exclude the transport-only
  `webhooks.verification` and `tests.test_event` events.
- Hookdeck sits in front of Ramp ingress. The inbound declaration detects `x-ramp-signature`
  and uses `x-hookdeck-eventid` as the delivery-id fallback.
- Ramp does not send a transport delivery-id header of its own, so the adapter never promotes
  the payload `id` into delivery identity.

## Current Writeback Status

No file-native writeback contract ships in this phase. `resources.ts` exports the read-mount
catalog that Cloud needs for discovery, layout, and auxiliary materialization, while mutation
templates remain deferred until the contract-backed writeback phase.
