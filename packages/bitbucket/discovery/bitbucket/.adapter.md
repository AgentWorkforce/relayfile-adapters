# Bitbucket Cloud Adapter

`@relayfile/adapter-bitbucket` exposes readable repository, project, pull request,
historical issue, commit, pipeline, deployment, and tag records under `/bitbucket`.
The adapter materializes canonical records, stable indexes, by-id mirrors,
lifecycle lookup aliases, and webhook normalization. Cloud can disable the
emitter's canonical write when its record writer has already written that path.

## Read Mount

| Resource | Canonical path | Lookup |
| --- | --- | --- |
| Repositories | `/bitbucket/repositories/{workspace}/{repository}/meta.json` | `/bitbucket/repositories/_index.json` |
| Projects | `/bitbucket/workspaces/{workspace}/projects/{key}.json` | `/bitbucket/projects/_index.json` |
| Pull requests | `/bitbucket/repositories/{workspace}/{repository}/pull-requests/{title-slug}__{number}.json` | `/bitbucket/pull-requests/_index.json`, `by-id`, `by-state`, `by-creator` |
| Historical issues | `/bitbucket/repositories/{workspace}/{repository}/issues/{title-slug}__{number}.json` | `/bitbucket/issues/_index.json`, `by-id`, `by-state`, `by-assignee`, `by-creator`, `by-priority` |
| Commits, pipelines, deployments, tags | `/bitbucket/repositories/{workspace}/{repository}/{resource}/{id}.json` | Resource `_index.json` and `by-id`; pipelines and deployments also have `by-status` |

Each repository resource root also has `_index.json`. Index rows include `id`,
`title`, `updated`, and `canonicalPath`. Read the canonical record by following
`canonicalPath`, or use the full by-id mirror.

## Operations

| Surface | Operation |
| --- | --- |
| Sync and webhook | Read-only materialization, including terminal lifecycle states |
| File-native writeback | Not supported |

Native Bitbucket Issues are retired. Historical records remain readable, but
the Issues sync does not auto-run and HTTP 410 must not delete cached records.
The pull-request schema is under `/discovery/bitbucket/repositories/{workspace}/{repository}/pull-requests/.schema.json`.
No `.create.example.json` is advertised because this adapter has no file-native
create operation. Provider IDs remain stable and path segments are URI encoded.
